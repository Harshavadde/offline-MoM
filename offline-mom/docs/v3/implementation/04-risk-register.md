# V3 Technical Risk Register

Mirrors [docs/v2/implementation/04-risk-register.md](../../v2/implementation/04-risk-register.md)'s format: every risk is tracked against a specific mitigation and a fallback — a mitigation reduces probability/severity, a fallback is what happens if the mitigation isn't enough. IDs are prefixed `RV3-` to stay distinct from the V2 register. No probability is stated as a number unless the PRD or repository evidence actually supports one — most below are qualitative (Low/Medium/High), matching V2's own convention for risks that haven't been measured yet.

**Last updated:** 2026-08-22, adding RV3-26 (R-10 Beginner Resume Flow's disclosed non-fabrication trade-off) — see [10-v3-progress.md](10-v3-progress.md)'s "R-10 — Beginner Resume Flow" section. RV3-01 through RV3-25 unchanged by R-6/R-7/R-8/R-9/R-10. **Status legend:** RESOLVED (the risk condition can no longer occur, verified) · MITIGATED (a real, verified mitigation exists and reduces the risk, but the underlying risk condition can still occur) · OPEN (no mitigation yet, or the mitigation is still unverified) · ACCEPTED (a disclosed, by-design limitation with no further mitigation planned). A test existing is not by itself grounds for RESOLVED — see each row's own evidence.
