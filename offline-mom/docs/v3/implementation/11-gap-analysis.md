## AI behavior and safety rules (PRD §6)

| ID | Rule | Status | Evidence |
|---|---|---|---|
| AC3-01 | Fabrication ban | 🔶 PARTIAL / MITIGATED | Every generative prompt is structurally bounded to one entry's existing text (verified by code review of `ResumeSuggestionPromptBuilder`) — but there is no way to verify the *model itself* never fabricates despite the instruction; this is inherently unverifiable by a test, only mitigable (see RV3-01, [04-risk-register.md](04-risk-register.md)). Not "✅ COMPLETE" because "the ban is stated and structurally bounded" is not the same claim as "fabrication cannot happen" |
| AC3-02 | Proposal-only (`SuggestedEdit` gate) | ✅ COMPLETE | Dedicated architectural test passes (`generate_resume_suggestions_use_case_test.dart`'s AC3-02 group); Accept is the only code path that ever calls `ResumeBlockRepository.setOverride` from AI-sourced content |
| AC3-03 | Deterministic fabrication backstop | ✅ COMPLETE (as flag-only) | `SuggestionFabricationGuard` exists, is unit-tested (17 tests), and is wired into the review UI — **flags, never auto-rejects**, exactly as the PRD's own text specifies (D-M3-04). Marking this ✅ reflects that the flag-only mechanism itself is fully built and correctly matches the PRD; it does not claim fabrication is prevented (that's AC3-01's own, necessarily-partial status above) |
| AC3-04 | Bounded scope (one entry + one requirement) | ✅ COMPLETE | Enforced structurally by `ResumeSuggestionPromptBuilder`'s signature and `GenerateResumeSuggestionsUseCase._firstMatchingRequirement`'s one-requirement-per-entry selection |
| AC3-05 | Graceful degradation | ✅ COMPLETE | Both stages tested: semantic-match failure → deterministic-only fallback (M2); LLM failure → per-entry skip, no batch failure (M3) |
| AC3-06 | Provenance never lost | ✅ COMPLETE | `SuggestedEditRepository.resolve()` never overwrites `original_value`/`suggested_value`; rejected/accepted rows remain queryable indefinitely |

## Summary

Of 17 functional requirements: **14 fully complete, 2 partially implemented** (FR3-05, FR3-13 — both the same underlying "JD title/company tag columns exist but are never populated" gap, disclosed and not blocking for beta), **1 unclear-by-nature removed** (FR3-16 is now fully complete and meaningfully tested, no longer merely vacuous). Of 6 AI safety rules: **5 fully complete (AC3-02 through AC3-06), 1 partial/mitigated-not-provable** (AC3-01 — inherently unverifiable that a model *never* fabricates, only that the architecture bounds and gates its output; this can never reach "complete" by construction, not a gap that further work would close). This is a substantial shift from the Milestone-3 baseline (previously: 8 complete, 7 partial, 2 not started) — Milestone 4 closed every remaining functional gap it targeted (import editability, template breadth at beta scope, model-upgrade path, writing-while-typing suggestions), and Milestone 5 closed the device-capability architecture gap (§22.4) and the privacy/PDF-metadata verification items, while honestly disclosing the three categories of verification (real-device, human-visual, full widget-test breadth) that remain genuinely outstanding rather than claiming them done.
